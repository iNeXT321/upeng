# 深度调研报告技能（Research Report Skill）

你现在需要按照下面的 SOP 完成一次"有证据支撑的调研 + 结构化报告输出"。
**禁止**在未搜索取证的情况下直接凭记忆撰写报告内容。

## 第 1 步：明确调研边界

从用户输入中提取以下要素，缺失的按默认值处理，**不要反问用户**（除非主题本身完全无法识别）：

| 要素 | 默认值 |
|---|---|
| 调研主题 | 必填，无法识别时才可反问 |
| 调研目的 | 供决策参考 |
| 时间范围 | 近 2 年，优先最新信息 |
| 地域范围 | 中国为主，必要时补充全球对比 |
| 输出格式 | HTML 网页报告（用户指定 ppt/markdown 时从其指定） |
| 报告篇幅 | 中等（5~8 个一级章节） |

## 第 2 步：拆解检索计划

把主题拆成 **3~5 个互不重叠的检索维度**。常见维度组合：

- 现状与规模（市场数据、用户量、增长率）
- 主要玩家 / 竞品（各自定位、差异点）
- 技术或方法论对比（优劣、适用场景）
- 政策与监管环境
- 趋势与风险

每个维度准备 1~2 个检索关键词。**检索关键词要短而准**，不要把用户整句话丢进搜索。

## 第 3 步：执行搜索取证

调用可用的搜索类工具（如 bocha 联网搜索 MCP）逐个维度检索：

1. 每个维度至少 1 次搜索；关键维度可追加 1 次细化搜索。
2. 优先采信来源：官方文档/官网、政府与监管机构、上市公司财报、权威媒体、行业研究机构。
3. **记录每条关键结论的来源**（站点名 + 标题 + 时间），第 6 步要用。
4. 搜索总次数控制在 8 次以内；某维度连续 2 次搜不到有效信息，就在报告中标注"该部分公开信息有限"，继续推进，不要卡死。
5. 如果搜索结果之间**存在矛盾**，保留双方说法并注明分歧，不要擅自选边。

## 第 4 步：交叉验证与筛选

- 关键数字（市场规模、增长率、价格、日期）至少要有 2 个独立来源，否则标注"单一来源，待核实"。
- 剔除明显过期信息（超出时间范围）与营销软文。
- 区分**事实**与**观点**：事实直接引用，观点需注明是谁的观点。

## 第 5 步：组织报告结构

按以下骨架撰写，章节可按主题增删，但**执行摘要、正文、风险、参考来源四块不可省略**：

```
1. 执行摘要        —— 3~5 条核心结论，每条一句话，读完即懂
2. 调研背景与范围   —— 目的、时间/地域范围、信息来源说明
3. 现状分析        —— 规模、格局、关键数据（配表格）
4. 对比分析        —— 玩家/技术方案对比（必须用表格，维度对齐）
5. 趋势判断        —— 3 个以内，每个都要有前文证据支撑
6. 风险与不确定性   —— 至少 2 条，含"本次调研的局限"
7. 结论与建议      —— 可执行的行动项，按优先级排序
8. 参考来源        —— 编号列表，与正文引用对应
```

需要报告模板的细化写法时，读取本技能目录下的 `references/report_template.md`。

## 第 6 步：选择输出方式

按优先级选择：

1. **有报告生成工具（如 report_tool）时**：调用它生成文件，`fileType` 按第 1 步确定的格式传入（html / ppt / markdown），
   `fileName` 用「主题_调研报告.html」这类中文前缀 + 正确后缀，`task` 参数里写清章节要求与需体现的数据细节。
   注意：报告生成工具**只负责产出文件，不要用它能查数据**，数据必须来自第 3 步的搜索结果。
2. **没有报告生成工具时**：直接在回复中输出完整 Markdown 报告，并在开头说明"当前环境未接入报告生成工具，以 Markdown 形式直接输出"。

无论哪种方式，都要遵守：

- 正文中的数据用**表格**呈现，不要堆成长段落
- 关键结论后标注来源编号，如 `[1]`
- 不编造数字、不编造来源、不编造引用链接

## 第 7 步：收尾

1. 用 3~5 句话向用户总结本次调研的核心结论。
2. 告知产出物（文件名/格式，或直接输出的报告）。
3. 主动说明本次调研的局限（哪些维度信息不足、哪些数据是单一来源）。
4. 如存在终止类工具（terminate），调用它结束任务；否则正常结束回答，不要再调用其他工具。

## 通用约束

- 全程使用中文输出（用户明确要求其他语言时除外）。
- 不要在思考过程中向用户暴露内部工具名。
- 不要重复生成内容相同或高度相似的报告。
- 若任务中途发现主题理解有误，先修正检索计划再继续，不要在错误方向上堆砌内容。
